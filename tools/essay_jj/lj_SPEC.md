# 經紀法規申論卡「邏輯拆解」資料撰寫規格

讀者：不動產經紀人考生（第三次應考）。目標是把每題拆成「子題 → 步驟 → 子題答案」，一份資料產生三種排法：
① 推理鏈（ask→law→fact→res，步驟間用 link 箭頭字說明上下關係）
② 條文｜本題 左右對照（lawh+law 在左，facth+fact 在右）
③ 地圖＋勾選（每步 key 一句短語 + checks 勾選清單）

## 經紀法規專用骨架（與民法差異）

步驟順序一律是 **法規 → 要件 → 本題 → 法律效果／罰則**：
- `lawh`/`law`：法規名＋條號＋該條要件（經紀業條例寫「§19Ⅰ 禁收差價」，公寓大廈寫「公寓§22Ⅰ①」，公平法寫「公平§25」，消保寫「消保§19Ⅰ」，行政命令寫「廣告處理原則第三點」）
- `fact`：本題事實怎麼套
- `res`（小結）：**罰鍰金額、期限、主管機關一律寫在這裡**，不要散在 law 或 fact

## 說明型題目（沒有案例事實）

題目若是「何謂…？」「…之規定為何？」這種沒有甲乙丙丁的說明題，整題物件加 `"example": true`。
加了之後「本題」欄會自動顯示成「舉例」，`fact` 就改寫成具體的舉例（例：在租屋網刊登物件、路口立招牌都算廣告），不要寫成「本題無事實」。

## 輸入

in_N.json 每題有：eid（鍵）、num、title、level、kw、question（原題）、full（完整四段式全文）、quick（考場速寫）、keys（得分關鍵詞＋常見失分點）、cites（該題條文卡清單）。

## 輸出：out_N.json，陣列，每題一個物件

```json
{
 "k": "es-fw06",
 "example": false,
 "subs": [
  {"q": "子題問句（照題目問法；題目問幾件事就幾個子題）",
   "pre": "（選填）進入本子題前的一句承接",
   "steps": [
     {"ask": "先問自己的一句話（白話問句）",
      "lawh": "§19Ⅰ 禁收差價與其他報酬",
      "law": "條文要件白話一句",
      "facth": "甲",
      "fact": "本題事實怎麼套（example 題寫具體舉例）",
      "res": "小結（一句）；罰鍰、期限、主管機關寫這裡",
      "key": "地圖用短語 ≤ 22 字，如「總額逾 6% → 違反 §19Ⅰ」",
      "link": "（選填）通往下一步的箭頭說明"}
   ],
   "ans": "子題答案一句，關鍵結論用 **粗體**"}
 ],
 "checks": [{"t": "law|fact|ans", "txt": "採分點一句", "sub": 1, "hot": false}],
 "mnem": "（選填）一句口訣",
 "flags": ["（選填）你發現原範文可能有錯或缺漏，寫給審核者看，不會上網頁"]
}
```

## 規則（務必遵守）

1. **只能用該題 full / quick / keys / cites 裡已經有的法律內容**。不得新增原內容沒有出現的條號、學說、判決、函釋。條號寫法沿用原文。覺得原內容缺了重要條文，寫進 flags，不要自己加。
2. 子題依「題目問幾件事」切。通常 1～3 個子題，每子題 2～5 步，全題 4～9 步。
3. **每個子題一定要有 ans，而且要直接回答該子題問句**：問「違反什麼規定」就寫出條號；問「如何處罰」就寫出處分種類與額度；問「有無理由」就寫有／無理由。原卡若漏了答案句，要從 full 的結論補出來。
4. 步驟順序＝推理順序。`link` 寫出「為什麼接著問下一步」。最後一步不需要 link。
5. checks：5～9 點，涵蓋每個子題的關鍵條文、關鍵涵攝與答案；t 只能是 law／fact／ans；sub 填所屬子題序號（1 起算）；hot=true 只標 keys 裡「常見失分點」對應到的那幾點（通常 2～3 點）。
6. 用語：繁體中文、白話、短句。人物沿用題目代號。不用 emoji。不寫「本站」「我們」。
7. 行政命令（說明書應記載事項、定型化契約、廣告處理原則）若 cites 標「要點整理」，lawh 要跟著標（例：「說明書應記載事項第3點（要點整理）」），不要寫成逐字條文。
8. JSON 必須合法（UTF-8、雙引號、不可有註解）。寫完用 python 讀一次確認可解析。
