# 土地法申論卡「邏輯拆解」資料撰寫規格

讀者：不動產經紀人考生（第三次應考），覺得現在的「必提重點」7 點混在一起、看不出上下關係、難記。
目標：把每一題拆成「子題 → 小問題步驟 → 條文／本題／小結 → 子題答案」，一份資料產生三種排法：
① 推理鏈（ask→law→fact→res，步驟間用 link 箭頭字說明上下關係）
② 條文｜本題 左右對照（lawh+law 在左，facth+fact 在右）
③ 地圖＋勾選（每步 key 一句短語 + checks 勾選清單）

## 輸入
in_N.json 每題有：k（鍵）、title、ek、question（原題）、full（完整四段式全文）、quick（考場速寫）、keys（得分關鍵詞＋常見失分點）、must（舊必提重點）。

## 輸出：out_N.json，陣列，每題一個物件
```json
{
 "k": "110-二",
 "subs": [
  {"q": "子題問句（照題目問法，若題目只問一件事就只有一個子題）",
   "pre": "（選填）進入本子題前的一句承接，說明與上一子題的關係",
   "steps": [
     {"ask": "先問自己的一句話（白話問句）",
      "lawh": "§87Ⅰ 通謀虛偽",           // 條號＋3～8字名稱；純推理步驟可為空字串
      "law": "條文重點白話一句",           // 與 lawh 同時為空或同時有
      "facth": "甲乙",                      // 右欄小標：本題的人/事/時點，2～8 字
      "fact": "本題事實怎麼套",
      "res": "小結（一句）",
      "key": "地圖用短語 ≤ 22 字，如「§87Ⅰ 通謀 → 無效」",
      "link": "（選填）通往下一步的箭頭說明，如「乙死了，丙丁繼承乙──那繼承到什麼、什麼時候？」"}
   ],
   "ans": "子題答案一句，關鍵結論用 **粗體** 標"}
 ],
 "checks": [
   {"t": "law|fact|ans", "txt": "採分點一句", "sub": 1, "hot": false}
 ],
 "mnem": "（選填）一句口訣，用箭頭串起推理順序；沒有好口訣就省略",
 "flags": ["（選填）你發現原內容可能有法律錯誤、前後矛盾、或題目子題原卡沒回答到的地方，寫給審核者看，不會上網頁"]
}
```

## 規則（務必遵守）
1. **只用該題 full / quick / keys / must 裡已有的法律內容**。不得新增原內容沒有出現的條號、學說、實務見解。條號寫法沿用原文（§87Ⅰ、§759-1Ⅱ、§1148 等）。若覺得原內容缺了重要條文，寫進 flags，不要自己加。
2. 子題依「題目問幾件事」切。題目若是「試問誰的主張有理由」這類單一問題，可以一個子題，但步驟要分出「爭點一、爭點二」的層次。通常 1～3 個子題，每子題 2～5 步，全題步驟 4～9 步。
3. 每個子題一定有 ans，且 ans 要直接回答該子題問句（何時→寫時點；有無理由→寫有／無理由；效力→寫有效／無效／效力未定）。原卡若漏了關鍵答案句（例如「丙丁根本沒取得所有權」），要從 full 的結論補出來。
4. 步驟順序＝推理順序（先前提、再要件、再例外、最後請求權基礎或效果）。link 寫出「為什麼接著問下一步」，讓人看得出上下關係。最後一步不需要 link。
5. checks：5～9 點，涵蓋每個子題的關鍵條文、關鍵涵攝與答案；t 只能是 law（條文）、fact（套本題）、ans（答案）。sub 填所屬子題序號（1 起算）。hot=true 只標「keys 的常見失分點」對應到的那幾點（通常 2～3 點）。
6. 用語：繁體中文、白話、短句。人物沿用題目代號（甲乙丙丁）。日期照題目。不用 emoji。不要寫「本站」「我們」。
7. 舊 must 第一點常被標成「定義」其實是法條——新資料不再有「定義」標籤，照 law/fact/ans 分。
8. 預測題（k 以「預」開頭）同樣處理。
9. JSON 必須合法（UTF-8、雙引號、不可有註解）。寫完用 python 讀一次確認可解析，且每題都有 subs、checks。

# 土地法專用補充（優先於上面的通則）
- 輸入 in_N.json 每題欄位：k、id、kind（off 官方／mock 補習班模擬卷／pred 預測／topic 自編專題）、cat（A～G）、title、question、full（完整四段式）、quick（考場速寫）、keys（閱卷關鍵詞＋常見失分點）、must（舊必提重點，可用作素材）、concl_must、trap（最容易漏）、cite（這題要背的條文）。
- **稅法題**（cat E、F，以及題目在問稅額、稅率、納稅義務人、減免的題目）：步驟順序改成「判斷稅目與納稅義務人 → 稅基／原地價 → 稅率或減免條件 → 算出結果」。lawh 放條號或公式名稱，law 放條文或公式；facth 寫「代入」或「本題」，fact 放數字代入；res 放金額或結論。沒有數字的稅法說明題，fact 用「舉例」並寫題目情境或範文例子。
- **法規題**（其他）：照民法骨架「法條 → 要件 → 本題 → 效果」。
- **說明題、比較題沒有事實時**：facth 寫「舉例」或「違反時」，fact 用範文裡已有的例子；範文沒有例子就寫要件逐項說明，不得自己編新的法律內容。
- 條號寫法沿用範文（土地法§34-1Ⅳ、土稅§33Ⅵ、平均§79-1、土徵§49Ⅰ①、都計§17Ⅱ）；條號一定要是範文 full／quick／keys／must／cite 裡出現過的。
- 範例：gold.json 有兩題已定稿（P29 稅法計算題、111-一 法規比較題），照這個水準與格式。
- 舊官方答案與現行法不同時，答案句寫現行法並註明「（考試年度官方答案依舊法為…）」，只限範文已有寫到的。
- 輸出到 out_N.json；flags 寫給審核者（不上網頁），例如範文前後矛盾、子題沒答、條號錯。
